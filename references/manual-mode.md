# 无 Python 环境的降级模式（manual）

脚本是加速器，不是前提。宿主没有 `python3`（沙箱禁用执行、Windows 只有 cmd、用户要求"别跑脚本直接判"）时，按本文件用**同一套规则表**人工执行，输出仍符合 `contract.md` 的形状，只是把可信度交代清楚。

## 一、什么时候进入 manual

- 执行 `python3 scripts/wanhua.py solve` 失败：`command not found`、`Permission denied`、沙箱禁止子进程。
- 宿主明确禁止运行代码，但允许模型按文档推理。
- 用户说"别装环境了，你直接判"。

先试一次脚本，再降级——不要因为"可能没有 Python"就直接跳过机器校验。

## 二、硬约定（manual 下的契约）

| 字段 | manual 下的取值 | 理由 |
| --- | --- | --- |
| `mode` | `"manual"` | 与脚本输出的 `decode` 区分，宿主可据此决定是否采信 |
| `confidence` | **`null`** | 没有脚本核验就不该给数字，禁止编 0.95 |
| `status` | 只用 `ok` / `low_confidence` / `ambiguous` / `unknown` | 人工不会"运行时崩溃"，不产 `error` |
| `rules` | 同一套 `R-*` 编号 | 保持可解释、可追溯 |
| `scope` | `[{token, weight, kind, scope}]`，`scope` 填你切出的小句原文 | 与脚本同形状，便于事后比对 |
| `explain` | 必须写明"manual 模式：按规则表人工执行，未跑脚本校验" | 让用户知道这是人判，不是机器判 |

manual 下**只允许判不准就 `ambiguous`**，不允许"看着像肯定就写肯定"。

## 三、手工执行卡（六步，与脚本同序）

### Step 0 切小句

按 `。 ， ； ： ？ ！ 、` 和连接词（但是 / 而且 / 因为 / 所以 / 虽然 / 如果 / 除非 / 即使 / 否则 / 才 / 就）切分；**每小句单独数否定**，跨小句的否定不参与同一次折叠。

### Step 1 圈否定词——先长后短

长构式（权重 **2**，必须整体划掉再数）：`不是不`、`并非不`、`不能不`、`不得不`、`没有理由不`、`未尝不可`、`不无`、`非…不可`、`无不`、`不是没有`、`未尝不`、`不免不`。

词汇化否定（权重 **1**）：`未必`、`难以`、`缺乏`、`避免`、`拒绝`、`否认`、`禁止`、`取消`、`排除`、`省去`、`免于`。

单字否定（权重 **1**）：`不`、`没`、`未`、`无`、`非`、`否`、`别`、`勿`、`莫`。

歧义类（**不计数**，直接标 `R-SPECIAL` → `ambiguous`）：`差点没`、`差点儿没`、`好不`、`难免不`。

### Step 2 折叠极性

合计权重，偶数 → 肯定，奇数 → 否定。权重 0 → `unknown`（`polarity: null`），不是绕弯句。

### Step 3 核作用域

两处否定之间夹着心理动词或助动词（`想 / 认为 / 觉得 / 希望 / 建议 / 打算 / 能 / 会 / 该 / 要`）时，标 `R-SCOPE` → `ambiguous`。理由：`不想不X` 与 `不［想不X］` 极性相同、意思相反，脚本也只能标风险，人更不能拍板。

### Step 4 查量词

否定后 8 字内出现 `都 / 全部 / 任何 / 一切 / 完全 / 一点 / 丝毫 / 所有 / 每个`，且与否定同小句 → 标 `R-QUANT`；此时全否降为部分否（`不是所有人都没意见` = 有人有意见）。

### Step 5 判层数与冲突

- 有效否定（不含歧义类）≥ 4 → `R-DEPTH`，`status` 至少 `low_confidence`。
- 同一句命中 ≥ 3 条规则 → `R-CONFLICT`，`status = ambiguous`。
- 冲突优先级：`R-CONFLICT` > `R-SCOPE` > `R-QUANT` > `R-LEXICAL` > `R-DEPTH`。

### Step 6 出结果

```json
{
  "skill": "double-negative-speech",
  "version": "1.2.0",
  "mode": "manual",
  "input_text": "不是不该改",
  "status": "ok",
  "polarity": "肯定",
  "confidence": null,
  "rules": [],
  "scope": [
    {"token": "不是不", "weight": 2, "kind": "construct", "scope": "不是不该改"}
  ],
  "pragmatic_hint": {
    "heuristic": true,
    "coverage": "有限覆盖：委婉软化 / 反讽 / 反问；不覆盖语气强度、礼貌层级、方言差异",

  },
  "explain": "manual 模式：按规则表人工执行，未跑脚本校验；否定权重合计 2，折叠为肯定",

```

## 四、降级会损失什么（别装没事）

- **词表靠肉眼匹配**：`没有理由不`、`未尝不可` 若被拆成两个单字，奇偶就翻面。必须先整体划掉再数。
- **作用域比脚本更粗**：脚本按标点与连词切小句，人只能靠动词线索猜；拿不准一律 `ambiguous`。
- **没有标注集兜底**：准确率无从量化，`confidence: null` 就是明说这件事。
- **对外文本要复核**：结论若进合同、公告、合规声明，补一句"建议在有 Python 的环境复核"。

## 五、可选替代方案

1. **换机器跑一次**：在有 Python 的环境执行 `python3 scripts/wanhua.py solve "<句子>"`，把 JSON 粘回当前会话，`mode` 用 `decode`、`confidence` 用真实值。
2. **只做最粗的一档**：只回答"肯定/否定/歧义"，不输出 `scope`、不解释规则——宁少不多。
3. **不要自己造第二套实现**：仓库不提供"零依赖单文件 HTML/JS 版"，两份规则并行必然漂移。真需要离线版，先开 issue 把你的运行环境写清，再评估是否值得维护。

## 六、manual 结果能不能当"已验证"

不能。`mode: "manual"` 的定义就是"未经脚本校验"。宿主若要把结论写进日志或对外输出，应保留这个字段，别把它抹成 `decode`。
